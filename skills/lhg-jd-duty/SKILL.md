# lhg-jd-duty：岗位职责撰写方法论

## 1. 何时使用

- 把"这个人来了要干嘛"翻译成 JD 里的职责条目时
- 职责写出来像"正确的废话"，自己都觉得虚时
- 评审别人的 JD，判断职责是否清晰、可衡量时

不适用：职责条数与要求条数的配比（见 `lhg-jd-structure` 第 3 节）、
任职资格写法（用 `lhg-jd-qual`）。

## 2. 输入与输出

**输入**：岗位的核心产出（"来了之后要对什么结果负责"）+ 3-5 句口头工作描述。

**输出**：4-6 条职责，每条动词开头、含具体对象与价值，无空话。

## 3. 核心公式：职责 = 动词 + 对象 + 范围 + 价值

一条合格的职责必须回答四个问题：**做什么动作、对什么东西、在多大范围、产生什么价值**。
四个里面至少要有前三个，第四个有最好。

示例拆解：
> "负责用户增长全链路运营（动词+对象），制定拉新与留存策略并推动落地（范围），
> 对 DAU 增长负责（价值）"

反例："负责用户运营相关工作"——动词有了，对象/范围/价值全没，等于没写。

## 4. 职责动词库（按场景选，开头必须用这些）

- **主导类**：负责、主导、推动、牵头——用于核心职责，表明 ownership
- **规划类**：制定、规划、设计、搭建——用于策略/体系类工作
- **执行类**：执行、跟进、落地、保障——用于推进类工作
- **优化类**：优化、迭代、复盘、监控——用于数据/效率类工作
- **协同类**：协调、对接、支持、带领——用于跨部门/带团队工作
- **开拓类**：开拓、拓展、策划、孵化——用于从 0 到 1 的工作

禁止用名词开头："团队的日常管理"→改成"负责团队日常管理"；
禁止用"协助/配合"开头写核心职责——协助是配角词，核心职责用它等于告诉候选人"这个活没分量"。

## 5. 条数与排序：4-6 条，第一条最重要

- **4-6 条是黄金区间**：少于 3 条显得岗位没含金量，多于 8 条重点被淹没
- **排序即权重**：候选人默认第一条是最重要的工作，面试也会围绕前 3 条问
- **合并同类项**：3 条都写"数据分析"相关的，合并成 1 条
- **删"顺带"职责**："顺带整理会议纪要"这种，写了拉低岗位档次，删掉

## 6. 空话清单（出现即删，或追问用户要具体内容）

| 空话原文 | 为什么不行 | 改写方向 |
|---|---|---|
| 负责相关工作 | "相关"是哪些？没人知道 | 追问：具体是哪几项工作，列出来 |
| 完成领导交办的其他事项 | 等于"什么都可能让你干" | 删掉；真有杂项，写"支持团队临时性专项工作"都比这个强 |
| 协助处理日常事务 | 日常事务=一切=什么都没说 | 追问：日常事务具体指什么 |
| 服从公司安排 | 契约精神呢？ | 删掉，JD 不是卖身契 |
| 不断学习提升自我 | 这是 JD 不是鸡汤文 | 删掉 |

改写原则：空话删掉后如果职责只剩 2 条，说明你对这个岗位的理解还不够——
回去问用人部门"这个人每天的时间花在哪三件事上"，问到具体动作再写。

## 7. 不同岗位的职责侧重点

- **运营/市场**：侧重对象是"用户/流量/活动"，价值是"增长/转化/留存"类结果
- **技术**：侧重对象是"系统/服务/架构"，价值是"稳定性/性能/效率"类指标
- **销售**：侧重对象是"客户/商机/回款"，价值必须量化（"对 X 万业绩目标负责"）
- **职能（人事/财务/行政）**：侧重对象是"流程/制度/员工体验"，价值是"效率/合规/满意度"
- **管理岗**：必须有一条写"带领 X 人团队"，不写带人规模的管理职责等于没写

## 8. 职责质量自查表

- [ ] 每条都是动词开头（负责/主导/制定…）
- [ ] 每条都能回答"做什么、对什么、在多大范围"
- [ ] 条数在 4-6 条，第一条是最重要的
- [ ] 无空话清单里的表述
- [ ] 合并了同类项，删掉了"顺带"职责
- [ ] 管理岗写了带人规模，销售岗写了业绩目标

## 9. 反模式

1. **职责要求不分家**：职责里写"本科以上学历"——那是要求，挪到任职要求里去。
2. **职责写成 KPI 表**：每条后面都跟"（KPI：DAU 提升 20%）"——JD 是招人的，不是下军令状的，价值点到为止。
3. **职责越写越长**：一条职责写 3 行还写不完——拆成两条，或者你根本没想清楚。
4. **全用"负责"开头**：6 条里 5 条"负责"——换动词库里的词，"负责"留给最核心的那 1-2 条。

## 10. 不同职级的职责差异（同一岗位，不同写法）

职责的"颗粒度"要和职级匹配，写错颗粒度等于招错人：

- **初级（1-3年）**：职责写"执行动作"，动词用执行/跟进/协助——
  "跟进活动上线全流程，保障各环节按时交付"。不要写"制定策略"，初级定不了策略，写了招来也不会。
- **中级（3-5年）**：职责写"独立闭环"，动词用负责/主导/推动——
  "独立负责用户增长项目，对 DAU 目标负责"。关键词是"独立"，能自己闭环。
- **高级（5-8年）**：职责写"体系与方法论"，动词用搭建/制定/沉淀——
  "搭建用户分层运营体系，沉淀可复制的方法论"。关键词是"体系"，能把经验变成组织资产。
- **管理（带团队）**：必须单列一条写带人——"带领 X 人团队，负责人才培养与梯队建设"。
  不写带人规模的管理职责，候选人默认你是"光杆司令"。
- **专家（不带人）**：写"技术影响力"——"主导核心架构设计，解决高并发场景下的稳定性难题"。
  专家岗的职责要让同行看了觉得"有挑战"，而不是"打杂"。

一句话检验：把职责读给目标候选人听，他如果说"这活我闭着眼都能干"——
职级写低了；如果说"这跨度也太大了"——职级写高了。

## 11. 职责改写实战：从口头到书面

用人部门给的永远是口头描述，翻译对照表：

| 用人部门原话 | 翻译成职责条目 |
|---|---|
| "就是打杂，什么都干点" | 拆：问出时间占比最高的三件事，各写一条；占比<10% 的不写 |
| "要个能干的" | 追问：能干=独立闭环？写"独立负责 X 项目全流程，对结果负责" |
| "帮老大分担点" | 追问：分担哪几块？写具体，"负责部门周报汇总与会议组织"都比"分担"强 |
| "有想法，能带团队冲" | 拆成两条："制定 X 业务年度规划" + "带领 X 人团队达成目标" |
| "最好啥都会" | 不可能，追问排序：按"没他不行"的程度排前 3，写 3 条 |

翻译三问（每次改写前问自己）：这条删掉，候选人会误解岗位吗？
这条外行能看懂吗？这条和上一条重复吗？三问都通过，才算翻译完成。

## 12. 自检与反馈

每次执行完本 skill，做一次轻量自检：

1. 每条职责都能通过"动词+对象+范围+价值"四问吗？→ 缺对象/范围的回去追问用户。
2. 空话清单里的表述清零了吗？→ 有一个就不许交付。
3. 条数在 4-6 条吗？第一条是最重要的吗？→ 不是就重排。
4. 职责里混进了任职要求吗？→ 有就挪走。

标准冒烟用例：用本 skill 改写插件 `fixtures/bad/a.md` 的职责章节，
跑 `scripts/audit/jd_audit.py` 确认 JD-STR-003（职责空话）与 JD-FMT-001（无动词开头）
不再命中（见仓库根 `smoke_test.py`）。

反馈渠道：以 `[QC] <一句话问题>` 为标题提交到 https://github.com/lhg-plugs/lhg-job-desc/issues，
正文写清"输入 → 错误输出 → 期望输出"。动词库补充请附使用场景。
