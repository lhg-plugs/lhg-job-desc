# lhg-jd-inclusive：包容性语言方法论

## 1. 何时使用

- JD 写完后，发布前的最后一道语言检查
- 评审别人的 JD，判断有没有歧视风险时
- 用人部门坚持要加"35岁以下""限男性"，需要反驳依据时

不适用：JD 结构（用 `lhg-jd-structure`）、职责写法（用 `lhg-jd-duty`）。

## 2. 输入与输出

**输入**：一份写好的 JD 文本。

**输出**：歧视词标注 + 中性改写建议 + 风险等级（blocker 必须改 / warning 建议改）。

## 3. 五类歧视词清单

### 3.1 性别歧视（blocker，见了就删）

限男性 / 限女性 / 只招男 / 只招女 / 男士优先 / 女士优先 / 男性优先 / 女性优先。

- 改写：删掉。如果岗位真有性别相关的客观要求（如女卫生间保洁），
  写具体工作场景（"负责女卫生间区域保洁"），而不是"限女性"。
- 注意：招聘文案里"小姐姐优先"这种看似亲切的表述，同样是性别歧视。

### 3.2 年龄歧视（blocker，见了就删）

35岁以下 / 30岁以下 / 年龄不超过 X / 年龄要求 X 以内。

- 改写：把"年龄"翻译成"经验"——"35岁以下"→"3年以上相关经验"。
  你真正想要的是"有经验但不太贵"，不是"年轻"，写出真实需求。
- 注意："团队年轻化""90后团队"这类描述，同样构成年龄暗示，建议删掉。

### 3.3 户籍地域歧视（blocker，见了就删）

限 X 户籍 / X 户口优先 / 本地人优先 / 外地人勿扰。

- 改写：真实需求如果是"要到岗办公"，就写"工作地点：北京，需到岗办公"；
  如果是"要懂方言"，就写"能熟练使用粤语沟通"。写出真实需求，不要拿户籍当代理变量。

### 3.4 婚育歧视（warning，强烈建议删）

已婚已育优先 / 未婚优先 / 单身优先 / 无生育计划 / 婚育情况。

- 这类表述除了涉嫌歧视，还极易引发舆情——截图一发，HR 和公司一起上热搜。
- 改写：删掉。如果担心稳定性，面试环节合法合规地了解，不要写进 JD。

### 3.5 外貌歧视（warning，建议删）

形象气质佳 / 身高 1X0cm 以上 / 长相端正 / 五官端正 / 颜值高。

- 除礼仪、模特等极少数对外形有客观要求的岗位外，一律删掉。
- 改写：如确需职业形象，写"注重商务礼仪，着装得体"——这是行为要求，不是外貌要求。

## 4. 换皮识别（改了词没改意思 = 没改）

审计脚本按关键词拦截，有人会把"限男性"改成"需要较强体力"蒙混过关——
本 skill 明确：**换皮同样判 blocker**。

| 换皮表述 | 真实意思 | 判定 |
|---|---|---|
| 需要较强体力，能搬重物 | 限男性 | blocker，写具体场景："需搬运 20kg 实验设备" |
| 希望年龄小一点，好培养 | 35岁以下 | blocker，写"3年以上经验" |
| 最好是本地人，稳定 | 限户籍 | blocker，写"工作地点 X，需到岗办公" |
| 刚毕业的优先，单纯好带 | 年龄歧视 | blocker，写"欢迎应届毕业生"（这是正向表述，可以） |
| 气质好，门面担当 | 形象气质佳 | warning，写"注重商务礼仪" |

识别方法：问"这句话删掉，会影响我们判断候选人能不能干好活吗？"
如果答案是"不会，只是我们想要个看着顺眼的"——那就是歧视，删。

## 5. 法律风险提示（常识版，不构成法律意见）

- 《就业促进法》明确规定用人单位招用人员不得实施就业歧视；性别、年龄、户籍限制都踩线。
- 残疾歧视、健康歧视同样碰不得："无传染病史""身体健康无残疾"这类表述不要写；
  特殊岗位（如食品行业健康证）写"需持有有效健康证"，这是法定要求，不是歧视。
- 舆情风险 > 法律风险：一份带歧视词的 JD 被截图传播，对雇主品牌的伤害远大于招错一个人。
- 拿不准时，原则是：**只写"能不能干好活"相关的要求**，其他的都不写。

## 6. 中性改写速查表

| 歧视表述 | 中性改写 |
|---|---|
| 限男性 | 删；或写具体工作场景 |
| 35岁以下 | 3年以上相关经验 |
| 北京户口优先 | 工作地点北京，需到岗办公 |
| 已婚已育优先 | 删 |
| 形象气质佳 | 注重商务礼仪（或删） |
| 身高170cm以上 | 删（除特殊岗位） |
| 名校毕业 | 本科及以上学历 |
| 大厂背景优先 | 有成熟体系的方法论沉淀 |
| 能吃苦耐劳 | 能接受项目制高强度工作（写清周期） |

## 7. 发布前必查清单

- [ ] 全文无 3.1-3.3 类 blocker 歧视词（跑脚本验证）
- [ ] 全文无 3.4-3.5 类 warning 表述，或已给出不删的书面理由
- [ ] 无第 4 节换皮表述（人工读一遍，用"那句话删掉影响判断吗"测试）
- [ ] 无健康/残疾歧视表述
- [ ] 学历表述为"X 学历及以上"，无"名校"字样

## 8. 反模式

1. **"我们老板要求的"**：老板的要求不是挡箭牌——出事背锅的是发 JD 的 HR。把本 skill 第 5 节给他看。
2. **"别人家都这么写"**：别人闯红灯不代表你也可以，何况现在截图举报只需要 3 秒。
3. **"我们这是委婉说法"**：委婉的歧视还是歧视，候选人看得懂，劳动部门也看得懂。
4. **只查中文不查英文**：英文 JD 里的 "male preferred""under 35" 同样中招，双语 JD 两版都要查。

## 9. 英文 JD 同样要查（双语发布必看）

英文 JD 的歧视表述更隐蔽，常见清单：

- "male preferred / female preferred"——性别歧视，删
- "under 35 / young and dynamic team"——年龄歧视，删；改成 "3+ years of experience"
- "native Beijing resident preferred"——地域歧视，改成 "based in Beijing, on-site"
- "good looking / presentable appearance"——外貌歧视，删
- "must be able to work under pressure"——本身不算歧视，但连写 3 遍等于预告血汗工厂，留 1 遍

双语 JD 检查流程：中文跑脚本 → 英文人工过一遍上表 → 两版语义对齐
（中文删掉的歧视词，英文版不能留着）。

## 10. 自检与反馈

每次执行完本 skill，做一次轻量自检：

1. 五类清单逐类扫过一遍了吗？→ 扫一遍只要 2 分钟，别偷懒。
2. 换皮测试做了吗？→ 每句可疑表述都过一遍"那句话删掉影响判断吗"。
3. 改写后跑脚本验证了吗？→ `scripts/audit/jd_audit.py` 确认 JD-INC-* 全不命中。
4. 用人部门坚持保留歧视词？→ 让他给出书面理由并签字，你的职责是提示风险。

标准冒烟用例：对插件 `fixtures/bad/a.md` 跑脚本，
确认 JD-INC-001 至 JD-INC-005 全部命中（见仓库根 `smoke_test.py`）。

反馈渠道：以 `[QC] <一句话问题>` 为标题提交到 https://github.com/lhg-plugs/lhg-job-desc/issues，
正文写清"输入 → 错误输出 → 期望输出"。歧视词库补充请附原文截图（脱敏）。
