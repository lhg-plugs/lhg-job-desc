# lhg-jd-qual：任职资格分级方法论

## 1. 何时使用

- 写 JD 的"任职要求"章节，不知道哪些该写、哪些不该写时
- 要求列了 10 几条，自己都觉得没人符合时
- 候选人嫌要求苛刻、HR 嫌简历太少，两头不讨好时

不适用：歧视词识别（用 `lhg-jd-inclusive`）、职责写法（用 `lhg-jd-duty`）。

## 2. 输入与输出

**输入**：岗位职责（已写好）+ 用人部门的"理想画像"口头描述。

**输出**：5-8 条任职要求，分/两级，条数 ≤ 职责条数×2。

## 3. 分级铁律：必备 vs 加分

- **= 缺一不可**：没有这一条，这个人来了干不了活。每一条必备都要能通过"反问测试"——
反问"如果候选人其他都很好、就缺这一条，我们还面吗？"如果答案是"面"，那它就不是必备，降级为加分。
- **= 有了更好**：有它如虎添翼，没有也能干。这是你用来在终面二选一时做决策的，不是用来筛简历的。
- **数量**：必备 3-5 条，加分 2-3 条。必备超过 5 条，说明你想要的是"超人"不是"候选人"。

示例：
> 3 年以上互联网用户运营经验，独立操盘过万级 DAU 增长项目
> 熟练使用 SQL，能独立完成数据复盘
> 有本地生活或电商行业经验
> 具备跨部门项目管理经验

## 4. 门槛设定四原则

1. **学历写"本科及以上"，除非真需要**：大部分岗位写"大专及以上"就够了；
写"硕士优先"之前先问：这个活真需要硕士，还是我们只是想筛人？
2. **年限写区间，不写"X年以上"一刀切**："3-5 年"比"3年以上"诚实——后者会收到 10 年经验的" overqualified "简历，浪费双方时间。
3. **技能写"能做什么"，不写"会什么工具"**："能独立完成数据复盘"比"熟练使用 Excel/SQL/Tableau"更能筛出真本事——工具可以学，能力不行。
4. **软素质最多 2 条**："沟通能力强/抗压能力强"写 1 条就够了，写 3 条等于告诉候选人"这活很磨人"。

## 5. 条数配比铁律

**任职要求条数 ≤ 岗位职责条数 × 2**。这是本插件审计规则 JD-STR-002 的来源。

- 职责 5 条 → 要求最多 10 条，超过就是"要干的活没多少，要求倒是一大堆"
- 失衡的 JD 会产生两种恶果：好候选人觉得"这公司事多钱少要求还高"直接划走；
留下来的都是海投碰运气的，面试成本翻倍
- 修法：要么合并要求（3 条软素质合成 1 条），要么把部分要求降级为"面试考察项"不写进 JD

## 6. 常见门槛表述对照

| 错误表述 | 问题 | 正确表述 |
|---|---|---|
| 35岁以下 | 年龄歧视，blocker | 3年以上相关经验 |
| 限男性 | 性别歧视，blocker | 能适应偶尔出差（如确有体力要求，写具体工作场景） |
| 北京户口优先 | 地域歧视，blocker | 工作地点北京，需到岗办公 |
| 名校毕业 | 学历歧视嫌疑，舆情风险 | 本科及以上学历 |
| 大厂背景优先 | 把 90% 的好候选人挡在门外 | 有成熟体系的方法论沉淀 |
| 能吃苦耐劳 | 等于预告"这活很苦" | 能接受高强度项目制工作（并写清项目周期） |
| 形象气质佳 | 外貌歧视，warning | 无（如确需对外，写"注重商务礼仪"） |

完整歧视词清单与法律风险见 `lhg-jd-inclusive`。

## 7. "招得到人"自查表

发布前逐项打勾：

- [] 每条都通过了"反问测试"（缺它真干不了活）
- [] ≤5 条，2-3 条
- [] 总条数 ≤ 职责条数×2
- [] 学历/年限表述无歧视嫌疑（对照第 6 节）
- [] 技能表述是"能做什么"而非"会什么工具"
- [] 软素质 ≤2 条
- [] 没有"不可能三角"（如 3年经验+名校+大厂背景 三者全要）

## 8. 反模式

1. **把"期望"写成"要求"**："希望有海外背景"——希望就别写进要求，写进去了就是筛人标准。
2. **要求与职责脱节**：职责写用户运营，要求写"有 Java 开发经验"——抄错模板了，对照职责重写。
3. **用要求掩盖管理问题**："能接受 996"——先问问自己，是岗位真需要，还是管理能力不行只能靠堆时间。
4. **加分项写成必备**：5 条必备里 3 条其实是"有了更好"——降级，必备多了等于没重点。

## 9. 写不进 JD 的，放到面试考察项

有些要求很重要，但写进 JD 会吓跑人或引发争议——转成"面试考察项"，不公开发布：

| 写不进 JD 的要求 | 为什么不写 | 面试怎么考察 |
|---|---|---|
| 能接受高强度加班 | 写了等于预告"这公司很苦" | 问"项目紧急时你最多连续加班多久"，看真实接受度 |
| 性格外向，善于社交 | 性格歧视嫌疑 | 无领导小组讨论，直接看表现 |
| 35岁以下（真实想法） | 年龄歧视，blocker | 删掉，用"3年以上经验"替代 |
| 希望是男生 | 性别歧视，blocker | 删掉，写具体工作场景 |
| 有大厂背景 | 把 90% 好候选人挡在门外 | 面试深挖方法论，看有没有体系化思考 |

原则：JD 只写"能不能干好活"的硬门槛；"合不合胃口"的软性判断，
留给面试环节——JD 是漏斗的入口，不是终面。

## 10. 加分项的正确用法：终面二选一的神器

加分项不是摆设，它的使用场景是"两个候选人必备项都满足，怎么选"：

1. **提前写下来**：JD 发布前就定好 2-3 条加分项，不要等到终面时拍脑袋。
2. **面试时验证**：针对每条加分项准备 1 个验证问题——
   "有电商行业经验"→"讲一次你操盘过的电商大促，复盘下转化漏斗"。
3. **决策时用**：A/B 必备项相当，A 有 2 条加分、B 有 0 条，选 A——
   这就是加分项存在的意义：把"感觉 A 更好"变成可解释的决策。
4. **不要倒置**：终面时因为候选人"有加分项"而放宽必备项——
   必备是底线，加分不能抵扣必备，倒置一次，JD 的分级就作废了。

一句话：必备决定"进不进面试"，加分决定"二选一选谁"。

## 10.5 证书类要求的写法

- 写"持有 X 证书优先"（加分），不要写"必须持有 X 证书"（必备）——
  除非法律强制要求（如律师执业证、医师资格证）。
- CPA/一建/PMP 这类证，写进必备会把"有能力但没考证"的人挡在外面；
  先问：这个证是"干活必需"，还是"我们觉得有证更靠谱"？后者一律降为加分。
- 语言证书同理："英语可作为工作语言"比"英语六级以上"更准——
  四六级高分开不了英文会的大有人在。

## 11. 自检与反馈

每次执行完本 skill，做一次轻量自检：

1. 每条必备都通过反问测试了吗？→ 没通过的降级为加分。
2. 总条数 ≤ 职责×2 吗？→ 超了就合并或转面试考察项。
3. 对照第 6 节，有歧视嫌疑的表述吗？→ 有一个就改掉。
4. 存在"不可能三角"吗？→ 有就砍掉最不重要的那一角。

标准冒烟用例：用本 skill 重写插件 `fixtures/bad/a.md` 的任职要求章节
（11 条→分级后 ≤6 条），跑 `scripts/audit/jd_audit.py` 确认
JD-STR-002（配比失衡）与 JD-LEN-001（条目过多）不再命中（见仓库根 `smoke_test.py`）。

反馈渠道：以 `[QC] <一句话问题>` 为标题提交到 https://github.com/lhg-plugs/lhg-job-desc/issues，
正文写清"输入 → 错误输出 → 期望输出"。门槛表述补充请附场景说明。
